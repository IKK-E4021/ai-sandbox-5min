AI Sandboxの実装パターン比較

同じSandboxでも実装はさまざま。Local OS Sandbox / Dev Container / Cloud Sandbox の3パターンで見る。

5分説明用
まず押さえること
Sandboxの本質はContainerかどうかではない。Filesystem / Network / Permission / Credential / Lifetime をどう制御し、Blast Radiusを小さくできるかが重要。
ざっくり使い分け
Local：軽く速い　／　Dev Container：再現性が高い　／　Cloud：Hostから切り離しやすい
Local OS Sandbox
Codex / Claude Code のローカル実行など
Mac / Linux Host
自分のPC上でAgentを動かす
OS Sandbox
Seatbelt / seccomp / Landlock など
/workspace RW~/.ssh NGNetwork制限
Hostには秘密情報や社内NWが存在 → Sandbox境界で触れないようにする
強み：起動が速く、対話的な開発と相性がよい
Dev Container
VS Code Dev Container / Dockerベース
Host PC
Dockerを動かす土台
Dev Container
ランタイム・ツール・Agentを内包
Java / NodeAI Agent再現性
↓
bind mountがRWなら、Container内の削除・変更がHostにも反映される
注意：Dev Container ≠ 自動的に安全なAI Sandbox
Cloud Sandbox
Copilot Coding Agent / Codex Cloud など
Ephemeral Sandbox
クラウド上の一時的な隔離環境
Repo cloneBuild/TestPR破棄
↓
出力

強み：Host PCから切り離しやすく、使い捨て前提と相性がよい
3パターンの比較
観点Local OS SandboxDev ContainerCloud Sandbox
隔離の単位プロセスContainerVM / Container / isolated env
Hostからの距離近い中間遠い
再現性やや環境依存高い高い
使い捨て中中〜高高い

一番伝えたいこと
Containerを使っただけでは不十分。
何を見せるか・何を実行させるか・どこへ通信させるか・秘密情報をどう隔離するかを設計する。
