Dev Container × GitHub Copilot CLI ― 実際にどう使う？

Copilot CLIそのものをDev Container内に入れて実行。さらにCopilot CLIのLocal Sandboxも有効化し、二重に境界を作る。

CLI実践例
Host PC
Dockerだけを動かす。Copilot CLIはHostではなくContainer内で実行する。
Docker / Dev Container
Dev Container = 第1の境界
JDK / Gradle / Git / GitHub Copilot CLIをContainer内へ固定
/workspaces/my-app
RepositoryはContainer Volume側にclone。ここで copilot を起動。
copilot ./gradlew test git diff gh / git
Copilot CLI Local Sandbox = 第2の境界
/sandbox enable で、Copilotが呼び出すShell・File tool等をOS Sandbox内へ。 CWDは書込可、Home/Systemは原則Read-only、その他はBlockという既定ポリシー。
Host ~/.aws
mountしない
Host ~/.ssh
mountしない
Docker socket
mountしない
この構成の狙い
① Copilot CLI自体をContainerに入れる AgentのShell実行・ファイル変更はまずContainer内に閉じる。Hostのユーザー環境と直接共有しない。
② その中でCopilot CLI SandboxもON Dev Containerだけに頼らず、Copilotが実行するコマンドをさらにOS Sandboxで制限する。
③ RepositoryもHostと分離 Hostの作業ツリーをRW bind mountせず、Container Volumeへclone。壊れたらVolumeごと捨てられる。
GitHub Copilot CLI Local Sandboxの既定値には注意 現在はLocal/Private NetworkとOutbound Internetが既定で許可され、Git / gh の認証情報も既定でSandboxへ提供される。必要に応じて /sandbox config で絞る。
実際の使い方
1
Containerを起動 RepositoryをContainer Volumeへclone。Hostの秘密情報はmountしない。

Terminalのイメージ
# Dev Container内
$ cd /workspaces/my-app

# Copilot CLI 起動
$ copilot --experimental

> /sandbox enable
Sandbox enabled.

> /sandbox policy
Filesystem:
  /workspaces/my-app   writable
  $HOME                read-only
  other locations      blocked

> このAPIにvalidationを追加して、
  ./gradlew test まで実行して

Copilot:
  - コードを検索
  - ファイルを修正
  - ./gradlew test
  - 失敗箇所を修正
  - 再テスト
安全寄りにするなら追加でここを絞る
FilesystemRepoはVolume。Host directoryのRW mountを避ける。
NetworkLocal networkや不要なInternet到達を無効化/Allowlist化。
Permissionnon-root、privileged禁止、Docker socketを渡さない。
CredentialGit / gh認証注入も必要性を判断。AWS本番鍵は渡さない。
Lifetime壊れたらContainer / Volumeを破棄して作り直す。
「二重Sandboxだから絶対安全」ではない Dev ContainerもCopilot CLI Sandboxも設定が重要。特に privileged、Docker socket、 過剰なbind mount、Credential注入、広いNetwork許可は境界を弱くする。
実運用のイメージ 「AgentにはWorkspace内ではかなり自由に実装・テストさせる。一方で、Host・本番Credential・不要なNetworkには到達させない。」
Dev Container × Copilot CLI = ContainerでHostから隔離 ＋ Copilot Local SandboxでAgentの操作をさらに制限
