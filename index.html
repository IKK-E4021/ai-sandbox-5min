AI Sandbox / 01

AI Sandboxとは何か

AI専用の「安全な作業部屋」。AIを信用するのではなく、失敗しても被害が広がらない境界を作る。

5分説明用
Sandboxなし
AIがコードを読む
↓
Shell / Git / Browser / Networkを実行
↓
誤操作・Prompt Injection
↓
Host / ~/.ssh / ~/.aws / 社内NWへ波及
AI Sandbox
部屋の中では自由に働かせる。
でも、外には勝手に出さない。
Blast Radiusを小さくする
Sandboxあり
Workspaceだけ読み書きOK
秘密情報は触らせない
Networkは必要先だけ許可
危険なOS操作はKernel側で拒否
壊れたら環境ごと破棄
Sandboxで制御する5つの軸
1. Filesystem
どのファイルを読める・書けるか。
/workspaceのみRWなど。
2. Network
どこへ通信できるか。外部送信・社内NW到達を制限。
3. Permission
どのOS機能・コマンドを使えるか。
4. Credential
AWS / GitHub / SSHなどの秘密情報をどう隔離するか。
5. Lifetime
環境を使い捨てにし、壊れても作り直せるか。
OSレベルではどう守る？
Seatbelt
macOS
プロセス全体をSandbox化
ファイル・ネットワークなどのアクセスをポリシーで制限する。
seccomp
Linux
「何をしてよいか」を制限
mount() や ptrace() など危険なSystem Callを拒否。
Landlock
Linux
「どこにしてよいか」を制限
/workspaceはOK、~/.sshはNGなどFilesystem範囲を限定。
AI Sandbox = 「AIが正しいことを期待する」のではなく、
「間違っても、ここまでしか壊せない」を環境側で保証する仕組み
